sec-check · scanner

Security check for your AI-built app

Apps made with Lovable, Bolt, Cursor, Replit and v0 tend to ship the same few mistakes: API keys in the frontend, Supabase tables without row-level security, and Firebase rules left in test mode. Pick your project folder to find them, along with a fix prompt you can paste straight back into your AI tool.

🔒 Runs entirely in your browser. Your code is never uploaded, stored or sent anywhere. Scan only projects you own or have permission to review.

Drop your project folder here

Or choose it below. node_modules, build output and lockfiles are skipped automatically.

Your browser may ask to "upload" the files. That's just its wording: they're only read on this page.

What sec-check looks for

Run it from the terminal or in CI

Same checks, no install needed (Node 18+). It exits with code 1 when it finds anything high or critical, so you can block risky deploys in CI.

npx github:tejamakkena/sec-check ./my-app
npx github:tejamakkena/sec-check ./my-app --json --fail-on=critical

To silence a finding you have checked, add sec-check-ignore in a comment on that line.

What it can't tell you

sec-check reads your source code. It doesn't connect to your database or website, so it can't see tables or rules you changed in a dashboard, and a clean result is not a guarantee. If you use Supabase, also run Advisors → Security Advisor in your project dashboard.
